# 论文工作流改造说明

已完成两条流程接入，.agents 与 .codex 下的同名工作台文件已同步。

## 语言打磨

中文：syw2039/humanizer-zh（已安装，下一轮可发现）。
英文：本机 humanizer。
混合稿按段落语言分别处理，不翻译术语，不对同一段连续使用两个 Skill。

工作台实际读取对应 Skill，使用嵌入模式处理工作副本；保留改写前基线、分章节力度、冻结数字/引用/术语、脚本语义锁和人工语义回归。原 qu-ai-wei 来源说明保留，不再作为运行时依赖。

## PDF 处理

有效规范缓存 → 直接复用。
没有缓存 → 自动调用本地 MinerU Desk → 查询到完成/复用 → 导出任务元数据 → 核验来源、完整页码和图片 → 生成 paper.md、source_map.json、conversion_manifest.json、conversion_report.md 和 assets → 更新项目索引与状态。

不可用时记录原因，使用原生本地转换降级，不自动上传云端。旧缓存不会因改造自动全部重做。

MinerU 会重新保存 _origin.pdf，因此来源核验使用 Desk 0.3.1 任务缓存键，核对当前原件指纹、转换参数与运行版本。复用任务追溯原始任务版本。Desk 原始产物与研究规范缓存分开保存。

## 本轮验证

- 本地 Desk 实际转换两页合成 PDF，成功导入 12 个块、4 处图片引用及完整页码。
- 规范缓存重复读取不重做转换，项目结构验证通过。
- Desk 复用任务成功导出并导入规范缓存。
- 缺图、缺页、未完成任务、部分页任务、云端任务、来源路径和缓存键不匹配被拦截。
- 本机原生文本降级可用。
- 中英文简短学术样例：去除冗余表达后语义锁通过；把样本数量从 12 改成 13 时拦截。人工比较确认原样例的对象、不确定性和因果限定保留。
- 两份工作台和两份 humanizer-zh 的 Skill 格式验证通过。

## 范围与限制

PDF 实测是两页合成样本，不代表所有扫描论文、复杂表格和公式均识别正确。仍需逐篇回查关键证据。
当前缓存适配器支持 Desk 0.3.1 的离线本地 Pipeline 和 content_list v1；未知结构明确失败，再按规则降级，不静默丢块。
本轮所用 Desk Python 没有 PyMuPDF，原生降级实测使用 pypdf；局部页面截图仍需要具备 PyMuPDF 的环境。本轮没有修改 Desk 随包依赖。
中英文润色验证为小样例；实际论文仍必须完成分节人工语义回归，脚本通过不等于全文语义完全一致。

## 使用

继续使用 $cyz-edu-research，给出论文项目或 PDF；无需手动轮流调用各个 Skill。
若直接运行 convert_pdf_to_md.py，它负责缓存探测、导入和原生降级；MinerU 的自动调度由工作台按 pdf-reading.md 执行。
