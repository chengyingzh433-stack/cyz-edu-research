# CYZ 教育研究工作台使用说明（v0.2 测试版）

> Skill 内部名称：`cyz-edu-research`  
> 适用领域：物理教学、科学教育、教育学与学习科学  
> 适用对象：研究经验较少，希望从研究灵感逐步走到论文成稿的学习者

安装位置：`C:\Users\cheng\.codex\skills\cyz-edu-research`

快速调用：

```text
$cyz-edu-research
```

## 1. 这套工作台解决什么问题

`cyz-edu-research` 是一套面向教育研究初学者的引导式研究与论文工作流。它不要求使用者预先熟悉研究方法，也不要求记住应调用哪个科研 Skill。

使用者只需说明自己目前有什么：可能什么想法都没有，也可能只有一个教学困惑、一个选题、一批文献、一份研究方案、一些数据或一篇草稿。工作台会判断当前阶段，解释眼前需要解决的问题，完成可以自动完成的工作，并在关键学术决策处请使用者确认。

它的核心目标不是“一键生成论文”，而是帮助使用者形成一条可检查、可追溯、可以暂停和继续的研究链：

```text
研究灵感或实践问题
→ 可研究的问题
→ 文献证据与研究缺口
→ 研究设计与伦理方案
→ 数据收集和分析
→ 论文各部分写作
→ 学术语言打磨与语义回归
→ 证据审查与正式输出
```

## 2. 最简单的使用方式

在 Codex 中输入 Skill 名称和当前情况即可：

```text
$cyz-edu-research
我没有选题，请带我从高中物理教学领域寻找值得研究的问题。
```

```text
$cyz-edu-research
我发现学生会套公式，但不能解释公式为什么适用。我想把这个现象做成研究。
```

```text
$cyz-edu-research
继续我的论文项目。
```

```text
$cyz-edu-research
请精读这篇中文论文，并把它加入当前项目的文献证据矩阵。
```

```text
$cyz-edu-research
我已经有研究方案，请从研究问题、样本、工具、分析方法和伦理方面帮我检查。
```

使用者不需要记忆阶段编号、内部模块名或复杂命令。工作台会自动判断应从哪里开始；无法可靠判断时，只询问一个最关键的问题。

### 2.1 与 KaiTi 的职责边界

开题范文提炼、开题写法知识库、开题报告起草和专项审查已经迁入独立的 `KaiTi` Skill。需要处理开题材料时使用 `$kaiti`；本工作台继续负责教育研究选题、文献、方法、数据分析和论文全过程。两个 Skill 的项目产物可以互相引用，但范文事实和引文不得作为研究证据。

## 3. 三种开始模式

### 3.1 灵感探索模式：目前没有研究念头

适用于“我想写论文，但不知道研究什么”。

工作台会先了解少量现实条件，例如研究领域、可能接触的学段和对象、可用时间及数据条件。随后开展有边界、可追溯的批量领域扫描。此阶段的目标是发现“有哪些方向值得继续看”，不是把每篇论文精读完。

1. 检索近期中文和英文综述、代表性实证研究、重要期刊议题及必要的政策材料；
2. 对较大批量的题目、摘要和可获得的结构化信息进行快速筛选；
3. 采用轻量的 `WHY / HOW / WHAT` 论文扫描：`WHY` 提炼论文要解决的问题或瓶颈，`HOW` 提炼研究方法和证据路径，`WHAT` 提炼主要发现、产出和未解决之处；
4. 在三项扫描结果上补充教育研究字段：研究方向、问题类型、研究对象、教育情境、理论、数据来源、主要变量或主题和作者所述局限；
5. 按主题聚类，统计常见方向、方法分布、研究对象与情境分布，以及近年的变化趋势；
6. 对少量代表性、相互矛盾或决定聚类边界的论文进行核查式阅读，防止仅凭摘要误判，但不默认制作逐篇完整导读卡；
7. 绘制主题、热点、争议、方法局限和被忽视情境的研究地图；
8. 生成若干候选研究方向，而不是过早生成完整研究方案；
9. 从学术价值、实践价值、创新可能、数据条件、伦理风险和完成难度等方面比较；
10. 推荐一个主方向和少量备选方向，并给出进入下一轮定向精读的文献清单，交由使用者确认。

“大量阅读”不等于声称穷尽整个领域。工作台必须记录数据库或来源、检索式、检索日期、筛选标准和实际阅读范围。未经定向复核，不得把“暂时没有检索到”写成“从未有人研究”。本轮依据多数情况下只达到题录级或摘要级，结论必须标明扫描深度；只有方向被确认后，才进入围绕该方向的全文筛选和标准精读。

灵感探索模式的默认成果不是几十份详细文献卡，而是一个“方向扫描包”：

- 每篇候选论文一份紧凑的 `WHY / HOW / WHAT` 卡片；
- 跨论文的共同 `WHY`、不同 `HOW`、最强 `WHAT` 和未解决问题；
- 方向、问题类型、方法、对象、情境、理论和变量的分布表；
- 代表性论文、相互矛盾论文和需要后续精读的论文清单；

- 领域扫描记录；
- 研究方向清单与主题地图；
- 研究问题类型分布；
- 研究方法、数据来源和分析方式分布；
- 研究对象、学段、学科与情境分布；
- 常见理论、变量或质性主题；
- 主要共识、争议和方法局限；
- 候选方向比较表；
- 每个方向的代表文献和证据级别；
- 方向确认后需要精读的优先文献清单。

### 3.2 选题推进模式：已有想法、现象或题目

适用于已经有教学困惑、研究方向、暂定标题或初步研究问题。

工作台会把宽泛想法逐步转化为可研究问题，重点检查：

- 研究对象和教育情境是否明确；
- 核心概念是否可以界定和观察；
- 问题属于描述、关系、差异、解释、干预还是其他类型；
- 能否获得回答问题所需的证据；
- 是否具有理论或实践价值；
- 是否能在现实时间、样本、方法和伦理条件下完成。

### 3.3 中途接入模式：已有材料或成果

适用于已有文献、综述、研究方案、数据、分析结果或论文草稿。

工作台先盘点材料，判断哪些阶段已经完成、哪些结论仍缺证据、哪些上游问题会影响当前任务，然后从第一个真正未完成的阶段继续。它不会要求使用者机械重走全部流程。

## 4. 每篇论文建立一个项目档案

每篇论文使用独立目录。Markdown 是研究过程的主档；Word、PDF 和 PPT 在开题、提交导师、投稿或答辩等节点统一生成。

建议结构如下：

```text
项目名称/
├─ 00-项目状态.md
├─ 01-研究起点与问题.md
├─ 02-文献/
│  ├─ 00-检索记录.md
│  ├─ 01-筛选记录.md
│  ├─ 文献卡/
│  ├─ 转换缓存/
│  └─ 核心文献精读/
├─ 03-文献证据矩阵.md
├─ 04-综述与研究缺口.md
├─ 05-研究方案.md
├─ 06-数据与分析.md
├─ 07-论文草稿/
│  └─ 学术语言打磨报告.md
├─ 08-审查与修改记录.md
└─ 09-正式输出/
```

`00-项目状态.md` 是续接工作的入口，至少记录：

- 当前阶段；
- 已确认的研究问题；
- 已完成成果；
- 尚缺材料和待核验事项；
- 当前阻塞项；
- 最近一次关键决定；
- 推荐的下一步。

再次使用时可以直接说“继续我的论文项目”。工作台先读取项目状态和相关成果，只从当前阶段继续，不重复已经确认的工作。

### 4.1 PDF 先转换为 Markdown 再阅读

当前顺序：检查已有规范缓存 → 缺缓存时自动调用本地 MinerU Desk → 验证完整任务、原 PDF 指纹和页码 → 接入 paper.md、图片、source_map.json 及索引。本地不可用时记录原因，回退到原生 PDF 转换；不自动转云端。旧的有效缓存继续复用，不因升级流程而全部重做。

语言打磨：中文调用 syw2039/humanizer-zh，英文调用 humanizer；混合稿按段落语言分配，术语不翻译。均保留改写前基线、分节力度、冻结内容、语义锁与人工语义回归。qu-ai-wei 的历史来源说明保留，但不再是运行时调用。

当论文是 PDF 时，工作台在标准精读或全文深读前，默认先建立可重复使用的 Markdown 缓存。这样后续查找研究问题、方法、样本、结果和局限时，不必每次重新解析整个 PDF，速度会明显更稳定。

每篇 PDF 的转换文件放在：

```text
02-文献/转换缓存/<paper-id>/
├─ paper.md                  # 按 PDF 页分隔的快速阅读文本
├─ assets/                   # 抽取图片和需要视觉核对的页面快照
├─ source_map.json           # 页码、文本块、图片和抽取方式的映射
├─ conversion_manifest.json  # 原 PDF 指纹及转换参数
└─ conversion_report.md      # OCR、排版和图表风险说明
```

批量转换后的统一入口是 `02-文献/转换缓存/00-缓存索引.md`，项目状态会同步记录已经可以直接复用的文献。

使用规则：

1. 原 PDF 始终是权威原件，`paper.md` 是唯一长期全文阅读缓存。
2. 正文按 PDF 页码分段，并加入稳定的文本块 ID。论文引用和证据定位使用“PDF 第几页 + 块 ID”，不能只使用 Markdown 行号。
3. 能直接抽取的图片放入 `assets/`；矢量图、组合图、复杂表格和公式主要通过页面快照保留。
4. 原生文字过少的页面会被标记为“需要 OCR”。这表示尚未可靠识别，不能把它当作空白页，也不能猜测其内容。
5. 精确引文、数字、统计符号、公式、图表和关键结论必须回到原 PDF 页面核验。
6. 转换器会记录原 PDF 的 SHA-256 指纹。文件未变化时直接复用缓存；原文发生变化时重新生成，避免新旧内容混用。
7. 旧的分页 TXT 会直接迁移成 Markdown，不会仅为换格式重新提取 PDF；验证成功后，位于 `tmp/pdfs/` 的 TXT 自动清理。
8. TXT 不会写入项目索引，也不作为正式阅读成果；表格、公式、双栏和图片只在精读相关页面时局部补充。

在没有选题的灵感探索阶段，不会把搜索到的每篇 PDF 都转换。多数论文只做题录和摘要扫描；只有代表性、相互矛盾、进入候选清单或使用者明确要求的论文才建立缓存。方向确定后，标准精读和全文深读的 PDF 默认执行转换。

使用者不需要记住转换命令，直接这样说即可：

```text
$cyz-edu-research
请先把这篇 PDF 转成带页码和图片映射的 Markdown 缓存，再做标准精读，并把可用证据更新到当前项目。
```

需要单独转换而暂不精读时，可以说：

```text
$cyz-edu-research
先把这些 PDF 建立 Markdown 阅读缓存，暂时不要做论文内容分析；请报告哪些页面需要 OCR 或视觉复核。
```

## 5. 完整工作流

### 阶段 0：领域扫描与灵感发现（可选）

仅在没有研究念头时启动。以批量、粗粒度、横向比较为主，提炼大量论文的研究方向、问题类型、研究方法、对象、情境、变量或主题和主要发现方向。产出领域地图、候选方向、初步证据来源、方法分布和可行性比较，不默认逐篇生成完整精读报告。

完成条件：使用者确认一个主方向，或者确认需要围绕少量候选方向继续定向检索。确认后才进入“方向落地模式”，对代表性和直接相关文献进行全文筛选、标准精读和研究问题聚焦。

### 阶段 1：从实践问题到研究问题

把教学困惑或研究方向转化为具体、可回答、可收集证据的问题。

主要产出：研究起点说明、核心概念表、候选问题比较、主研究问题与必要的子问题。

完成条件：问题的对象、情境、概念、证据需求和可行性均达到可继续检索与设计的程度。

### 阶段 2：文献检索设计

根据研究问题拆分中英文核心概念，建立同义词和相关词，选择合适数据库或来源，制定纳入和排除标准。

主要产出：检索矩阵、检索式、数据库与来源清单、检索记录、筛选规则。

完成条件：检索过程可以被复查，文献选择不完全依赖随意浏览。

### 阶段 3：文献筛选与分级阅读

先筛选相关性和质量，再决定阅读深度。并非所有论文都需要全文逐段阅读。

主要产出：筛选记录、文献卡、核心文献精读文件和文献证据矩阵。

完成条件：与研究问题直接相关的主要证据已被结构化记录，关键结论能定位到原文或页码。

### 阶段 4：文献综合与研究缺口

按主题、理论、方法、对象、情境或结论组织文献，分析共识、分歧、条件差异、证据边界和方法局限。

主要产出：主题综合、研究争议、候选缺口、缺口复核记录、文献综述框架。

完成条件：研究缺口能够回答“前人已经知道什么、解释在哪里受阻、本研究从哪里进入、为什么值得进入”。

### 阶段 5：研究设计

依据研究问题选择量化、质性、混合研究、准实验、调查、访谈、课堂观察、案例研究、行动研究或其他适当方法。方法不能因为熟悉或流行而被强行套用。

主要产出：研究问题—证据—方法对齐表、研究对象与抽样方案、工具和测量方案、实施程序、分析计划、伦理与数据管理方案。

完成条件：每个研究问题都有可获得的数据和匹配的分析方法；每项数据都有明确用途；结论强度不超过设计能够支持的范围。

### 阶段 6：数据收集与分析

在真实数据基础上检查数据质量、缺失、异常、编码和分析条件，选择与问题、设计及数据类型匹配的分析方法。

主要产出：数据字典、清理记录、分析计划、分析结果、图表、质性编码或主题结果、可复核的分析说明。

完成条件：结果能够逐项回答研究问题，统计或质性分析过程透明，不隐藏不显著结果或反向证据。

### 阶段 7：论文写作

按照“问题—证据—推理”完成摘要、引言、文献综述、研究方法、结果、讨论和结论。可以逐节写作，也可以根据已有草稿修订。

主要规则：

- 摘要概括真实问题、方法、结果和贡献；
- 引言从现实与学理背景导出研究问题；
- 综述按主题综合，不逐篇罗列；
- 方法提供理解和复核研究所需的信息；
- 结果报告发现，不提前编造原因；
- 讨论解释发现、比较文献、限定边界并说明意义；
- 结论不超出设计、样本和数据支持范围。

当工作台实际起草或重写了中文或英文论文正文，或使用者要求“去 AI 味”“改得自然”时，工作台会在实质内容基本定稿后默认启动内置的学术语言打磨子流程；使用者可以明确说“用户跳过”。它先保存改写前基线，再按论文部分采用不同强度：引言、综述和讨论可以适度调整；摘要保守调整；方法和结果只做轻度语言整理；研究问题、假设、量表题项、统计量、引文、公式和参考文献默认冻结。

改写前先记录文本来源门检：AI 辅助生成、真人原稿、混合稿或不确定。真人原稿或来源不确定时默认只诊断，不整篇重写。打磨完成后必须进行两类复核：确定性语义锁检查用于比较数字、统计表达、引文、DOI、图表编号、研究问题编号、占位符和锚点顺序；人工语义回归用于检查研究对象、情境、结果方向、因果强度、限定词、反向证据和结论边界。发现漂移时回到改写前版本缩小修改范围，不能从记忆补写。

### 阶段 8：全文审查与正式输出

从研究问题、文献证据、研究设计、结果、讨论、引用、语言和格式等方面审查全文，修复上下游不一致。

主要产出：问题清单、修改记录、证据核验表、最终 Markdown，以及按需要生成的 Word、PDF、PPT 或答辩材料。

完成条件：关键主张都有可靠依据，待核验内容已经处理，标题、摘要、问题、方法、结果和结论保持一致。

如果执行过学术语言打磨，阶段 8 还要求保留改写前基线、语义锁结果、人工语义回归记录和已审查范围。语言打磨不能承诺规避 AI 检测，也不能替代学校、期刊或项目要求的 AI 使用披露。

## 6. 工作台怎样与初学者互动

默认采用“阶段内自动工作、阶段末确认一次、知识按需讲解”的方式：

```text
说明当前任务及其必要性
→ 自动完成可以安全完成的检索、整理或分析
→ 展示阶段成果
→ 使用检查表指出问题
→ 推荐一个方案并说明理由
→ 请使用者确认一个关键决定
→ 保存进度并说明下一步
```

机械工作尽可能自动完成；以下关键学术决策不得悄悄代替使用者决定：

- 最终研究问题；
- 核心概念与理论框架；
- 研究对象和情境；
- 研究方法与重要设计取舍；
- 变量、工具和关键操作化方式；
- 对研究结果的核心解释；
- 论文最终主张和贡献边界。

每次只解释当前真正需要的知识，并优先使用物理教学或教育研究例子。不要一次性向初学者倾倒整套研究方法课程。

### 6.1 单问题引导协议

工作台吸收 `grill-me` 的核心访谈方式，用于选题、研究问题、方法选择、解释结果和确定论文主张等关键决策：

1. 先识别当前决定依赖哪些上游事实和已经确认的决定；
2. 能从项目文件、论文、数据库或工具中查到的事实，由工作台自行查找，不反问使用者；
3. 每次只提出一个需要使用者判断的问题；
4. 每个问题同时给出工作台的推荐答案、理由和主要取舍；
5. 使用者回答后，将决定和理由写入 `00-项目状态.md`；
6. 先解决上游决定，再进入依赖它的下游决定；
7. 对当前阶段达成共同理解后，才执行会固化方向的实质工作。

默认采用温和、教学式表达，不使用审讯式语气。只有在使用者明确要求“严格质疑”“压力测试”或“模拟评审”时，才提高追问强度。

单问题引导不是要求每一步都停下来提问。文件整理、格式转换、去重、状态更新、已确认规则下的批量提取，以及不改变研究方向的格式检查可以自动处理。以下情况必须进入单问题引导：

- 在多个候选研究方向之间选择；
- 确认主研究问题或删除某个子问题；
- 确定研究对象、理论框架、方法或关键测量；
- 在价值、创新、可行性和伦理之间作取舍；
- 解释意外结果或确定论文核心主张；
- 现有材料允许两种以上合理但后果不同的路径。

## 7. 文献阅读的三级机制

### 7.1 快速筛选

用于较大批量文献。至少记录：题目、年份、来源、研究对象、研究问题、方法、主要发现、与当前问题的相关性和保留决定。

输出结论为：纳入标准精读、保留备查、排除，并说明原因。

### 7.2 标准精读

用于与研究问题直接相关的大部分重要文献。文献卡至少包括：

- 完整题录及可追溯位置；
- 研究背景和研究问题；
- 核心概念与理论框架；
- 研究对象、情境与抽样；
- 研究设计、数据来源和工具；
- 分析方法；
- 主要结果及其证据；
- 作者的解释和结论；
- 研究局限；
- 证据强度与可迁移边界；
- 与当前项目的关系；
- 可支持的观点与不能支持的观点；
- 需要继续核验的问题。

中文论文直接制作中文结构化文献卡。英文论文默认也制作中文文献卡，保留关键英文术语和重要原句定位。

### 7.3 全文深读

仅用于核心理论、关键实证研究、需要复现的方法或直接影响研究设计的论文。必要时形成逐段或分节中英对照、图表说明、页码或文本块定位、术语表和批判性阅读记录。

全文深读不能代替综合。每篇读完后仍需把可用证据写回文献证据矩阵。

### 7.4 初学者导读与重点标记

在方向已经初步确定后的标准精读中，工作台不能只生成供机器检索的文献卡，还要提供一份面向初学者的“论文导读卡”。导读卡先用通俗语言讲清论文，再保留专业信息和原文位置。灵感探索阶段只对少量需要核查的代表性论文生成简版说明，不默认逐篇制作完整导读卡。

每篇关键论文至少回答：

1. **为什么现在读这篇**：它与当前探索方向有什么关系；
2. **一句话讲明白**：作者研究了什么问题，得出了什么主要发现；
3. **研究是怎样做的**：对象、情境、方法、数据和分析方式；
4. **最值得记住的三点**：逐点解释其价值，而不是只摘抄原句；
5. **证据是否可靠**：设计支持什么程度的结论，有哪些替代解释；
6. **作者没有解决什么**：样本、情境、理论、方法或机制方面的边界；
7. **对当前选题有什么启发**：可以借用什么、改进什么、继续追问什么；
8. **还不能得出什么结论**：防止把相关写成因果或过度推广；
9. **关键术语解释**：只解释理解本文所必需的概念；
10. **原文依据在哪里**：标注页码、章节、表格、图或可追溯文本位置。

重点不能仅按“看起来重要”或出现次数来划分，应依据它对研究链的作用进行标记：

| 标记 | 需要标出的内容 | 后续用途 |
| --- | --- | --- |
| `[问题]` | 研究要解释的现象、矛盾或困难 | 形成选题和研究问题 |
| `[理论]` | 核心概念、理论关系和解释机制 | 建立理论框架 |
| `[方法]` | 设计、样本、工具、程序和分析 | 设计自己的研究 |
| `[证据]` | 直接支持主要发现的数据、图表或引文 | 支撑综述和讨论 |
| `[结论]` | 证据允许作出的判断 | 比较研究共识与分歧 |
| `[局限]` | 作者承认或审读发现的证据边界 | 判断研究缺口 |
| `[启发]` | 对当前项目可能有用的追问或改进 | 生成候选研究点 |
| `[待核验]` | 只有摘要、二手转述或定位不可靠的内容 | 后续回到原文核实 |

工作台在阅读一批论文后，还应提供一次横向讲解：哪些论文观点一致，哪些互相冲突，差异可能来自什么样本、情境、工具或方法，以及这些差异能否形成值得继续检索的研究问题。这样“精读”最终形成理解和判断，而不是积累大量互不连接的摘要。

## 8. 文献证据矩阵

文献证据矩阵是检索、精读、综述、研究缺口和讨论部分之间的连接器。建议至少包含：

| 文献编号 | 主题 | 研究问题 | 理论 | 对象与情境 | 方法与数据 | 主要结果 | 局限 | 证据质量 | 与本研究关系 | 原文位置 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

工作台不得只积累摘要。它需要横向比较多篇研究，识别：

- 已形成的共识；
- 相互矛盾的结果；
- 结论成立的条件；
- 理论、方法、样本、情境、时间或机制方面的局限；
- 可以形成研究问题但仍需复核的候选空白。

## 9. 证据状态与学术诚信

所有影响论文主张的材料使用统一状态：

| 状态 | 含义 | 能否进入最终论文 |
| --- | --- | --- |
| `已核验` | 已回到原始论文、数据或权威来源确认 | 可以 |
| `待核验文献` | 暂时只有二手转述、摘要或不完整来源 | 核验后才可以 |
| `研究者推断` | 使用者基于证据作出的解释 | 需要明确论证 |
| `AI建议` | AI 生成的候选思路或表达 | 不能直接作为证据 |
| `待补材料` | 缺少样本、工具、数据或实施信息 | 补充后才可以 |
| `不可使用` | 虚构、无法追溯或明显超出证据 | 不可以 |

硬性规则：

- 不虚构作者、题目、期刊、年份、DOI、页码或引用；
- 不虚构样本、量表、信效度、统计量、访谈内容或研究结果；
- 不把相关关系写成因果关系；
- 不把局部样本无条件推广到所有学生或课堂；
- 不把课程笔记当作论文事实依据或替代原始文献引用；
- 不隐藏与假设不一致、不显著或无法解释的结果；
- 证据不足时允许保留明确占位符，但最终输出前必须处理。

## 10. 内置知识包

Skill 将吸收并去重以下两类课程资料中的可操作内容：

1. 教育研究方法：研究范式、选题、研究问题、文献检索与评价、抽样、数据收集、量化与质性分析、伦理、研究计划书和生成式 AI 使用；
2. 论文写作课程：选题论证、摘要、引言、文献综述、研究方法、结果、讨论、局限、评审视角和写作检查。

知识包按工作阶段拆分，不复制总笔记与分册中的重复内容。关键规则保留来源说明和需要谨慎理解之处。知识包用于指导研究与写作，不能代替论文中的原始学术来源。

## 11. 内部功能模块

`cyz-edu-research` 只有一个对外入口，内部按需加载功能模块：

| 内部模块 | 主要任务 |
| --- | --- |
| `guided-mentor` | 基于 `grill-me` 的单问题引导、推荐答案和决策依赖管理 |
| `idea-scout` | 基于 `WHY / HOW / WHAT` 的批量论文扫描、主题地图和灵感发现 |
| `question-builder` | 从现象或方向形成可研究问题 |
| `literature-search` | 中英文检索设计、记录和更新检索 |
| `paper-screening` | 相关性、质量和阅读级别判断 |
| `paper-reading` | PDF 转 Markdown 缓存、中文与英文文献的三级精读 |
| `evidence-synthesis` | 文献证据矩阵、主题综合和争议分析 |
| `gap-finder` | 候选研究缺口生成与检索复核 |
| `study-designer` | 教育研究方法、抽样、工具、程序与伦理设计 |
| `analysis-planner` | 数据质量、量化或质性分析方案 |
| `paper-writer` | 论文各部分起草与修订 |
| `academic-humanizer` | 按中文/英文调用 humanizer-zh/humanizer；保护作者声音，执行语义锁与改写后回归检查 |
| `integrity-auditor` | 证据、引用、逻辑、方法和全文一致性审查 |
| `output-builder` | 最终 Word、PDF、PPT 等交付文件生成 |

这些是工作台内部模块。语言模块自动调用已安装的 humanizer-zh（中文）或 humanizer（英文），PDF 模块优先调用 mineru 接入本地 MinerU Desk；使用者无需手动切换 Skill。它们可以吸收现有成熟科研 Skill 中适合本项目的流程、检查规则与模板，但应完成教育研究适配、重新组织，并保留必要的来源和授权说明。

## 12. 外部条件与降级处理

研究工作台保留自己的项目、证据和审查规则，外部 Skill 负责专门处理；不表示所有外部服务都能离线获得。当前语言打磨依赖 humanizer-zh（syw2039 版本）和 humanizer；PDF 解析优先依赖本地 mineru Skill 与 MinerU Desk，保留原生转换降级：

- 在线检索需要网络，部分数据库可能需要机构权限或人工登录；
- 无法取得全文时，只能把结论标记为摘要级或待核验；
- 扫描版 PDF 的识别质量取决于 OCR 和页面质量；
- 复杂统计分析需要可用的软件环境及真实、结构清楚的数据；
- Word、PDF 或 PPT 输出依赖相应的文档处理环境。

遇到能力不足时，工作台必须明确说明缺失条件、已经完成到哪里以及可行替代方案，不得用猜测补齐。

## 13. 常用示例

### 没有选题

```text
$cyz-edu-research
我目前没有选题。我能接触高中物理课堂，希望从近五年的研究中寻找可实行的方向。请启动灵感探索模式。
```

### 从教学问题开始

```text
$cyz-edu-research
学生做电磁学题时会使用公式，但不能解释物理条件。请一步步帮我把它转化成研究问题。
```

### 制订检索方案

```text
$cyz-edu-research
当前研究问题已经确认。请生成中英文检索矩阵、数据库方案和纳排标准，先不要写文献综述。
```

### 精读中文论文

```text
$cyz-edu-research
请对这篇中文教育研究论文做标准精读，保留页码依据，评价研究设计，并更新当前项目的文献证据矩阵。
```

### 检查研究设计

```text
$cyz-edu-research
请检查我的研究问题、样本、问卷、访谈和分析计划是否对齐。先列出不能由现有证据回答的问题。
```

### 只上传开题范文

上传多份开题报告、学校模板或导师批注后，只需发送：

```text
$kaiti
提炼这些开题范文。
```

KaiTi 会建立独立的开题项目。它不会把范文中的选题事实、数据和参考文献当作当前研究的证据，也不会在质量标签缺失时把高频写法称为优秀写法。

### 写作讨论部分

```text
$cyz-edu-research
根据当前项目中已核验的结果和文献证据矩阵起草讨论。不得新增数据或未经核验的文献。
```

### 学术终稿去 AI 味

```text
$cyz-edu-research
论文内容已经基本定稿。请先确认 S7 实质内容闸门，再按学术语体进行去 AI 味打磨；保存改写前基线，保护研究问题、术语、数字、统计量、引文和结论边界，完成语义锁、人工语义回归和第二次语言检查后再进入 S8。
```

### 继续项目

```text
$cyz-edu-research
继续项目。读取项目状态，从第一个未完成的质量关卡开始。
```

## 14. 测试与迭代

第一版完成后必须先验证结构，再进行真实场景测试。建议至少覆盖：

1. 无研究念头：能否从物理教学领域扫描到有证据、可实施的候选方向；
2. 模糊困惑：能否形成边界清楚、可以收集数据的研究问题；
3. 中文论文精读：能否准确提取问题、样本、方法、结果、局限和原文位置；
4. 英文核心文献：能否保留术语、证据位置和必要的中英对照；
5. 项目续接：中断后能否根据项目状态继续，不重复已经完成的步骤；
6. 方法匹配：能否发现研究问题、数据和分析方法之间的不一致；
7. 证据拦截：能否阻止虚构引用、未经核验主张和过度因果推断进入终稿；
8. 中途接入：能否正确处理已有研究方案、数据或论文草稿；
9. 学术语言打磨：能否降低模板化表达，同时拦截数字、引文、术语、限定词和结论边界漂移；
10. 最终输出：Markdown 主档与 Word/PDF/PPT 是否一致且完整，且主稿哈希与审查通过版本一致。

每轮测试记录：输入场景、预期行为、实际输出、失败原因、需要修改的模块和复测结果。第一版以“能稳定引导并保持证据边界”为合格标准，不以功能数量为标准。

## 15. 第一版边界

第一版重点服务中文物理教学和教育学研究，包括教育类实证论文、开题报告、研究计划书与学位论文。支持文献综述作为完整研究阶段，也可以辅助撰写综述文章。

第一版不以自然科学实验论文、Nature 风格英文论文、元分析、复杂结构方程模型、全自动数据库抓取或无人确认的一键成稿为主要目标。遇到这些任务时，可以在保留项目档案和证据规则的前提下扩展专门模块。
